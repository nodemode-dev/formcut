# interface architect

The interface: vanilla TypeScript, Vite, no framework, no icon dependency. Load `references/interface-map.md` for the module inventory and the command list.

## The state engine

`engine/project.ts` owns the document. Commands mutate it, history is pushed by the mutating commands themselves, and `emit(changed)` notifies subscribers. The only names emitted are clips, playhead, transport, timeline, project and clip-selection. A subscriber filtering on any other string silently never runs, which has cost this project two debugging sessions.

The transport accepts an optional clock source. While audio is scheduled, the playhead follows the audio clock; otherwise it accumulates wall-clock deltas. Two clocks cannot be reconciled, only chosen.

## Panes and containering

Each pane is built once and reconciled in place: nodes are matched by id and only changed values are written. Nothing rebuilds a container, because a rebuild costs focus, scroll and any canvas already drawn. `styles/containers.css` carries the shared anatomy (`panel-section`, its head, `panel-rows`, `panel-row`, `panel-note`) and the panes adopt it through the class names they already have.

Stylesheet order in `main.ts` is load-bearing: tokens, creator, app, themes, containers, settings. The shared sheet sits between the app's own styles and the popout's so the popout keeps the last word about itself.

## Extensions

The Extensions tab is a library-style view (`ui/extensions.ts`, `{ el, tab, load, pause }`) in the media pane's tab list; the Extensions menu is a fourth titlebar `.menu-item`. `extensions/host-bridge.ts` is the contract kit's file and stays unchanged; wrap it. `extensions/catalogue.ts` is the only door from an extension to the document: an allowlist of engine commands with argument checks, run inside `ProjectEngine.transaction`, which makes every `pushHistory` in the call record into one delta and puts the document back when anything throws. Toasts from outside the titlebar go through the `formcut:toast` document event.

## Appearance and locale

29 profiles are generated by `setup/gen_appearance.py` into `styles/themes.css`: 28 from one ladder table, and Studio, the form family's default shared with formvfx, from fixed values in its `FIXED` table; edit the tables and regenerate rather than tuning a value. The family chrome (`--rim`, `--head`, `--raise`, `--raise-edge`, `--cue-soft`, `--cue-line`, `--cue-ink` in `tokens.css`) is derived from each profile's tokens, with a light-profile override: a chosen tab is a raised pill with an inset ring (never a border, so turning it on cannot shift layout), and a primary action or an on control is the accent as a tint with a line, not a solid fill. A profile names a default accent; a chosen accent is an inline custom property on the root, which wins, and clearing it falls back. Derived accent values are computed once at choice time and stored so the pre-paint boot script in `index.html` can apply them verbatim before the first frame.

Strings live in `i18n/en.json`, `es.json`, `de.json` and the generated `language-pack.ts` carrying nine more locales as pipe-separated rows. Every row has the same column count; a blank line in that table throws at boot and blanks the app, which has happened once.

Active states carry the accent since v0.54.0: `.pane-tab.is-active` and `.seg > button.is-active` fill with `--cue` and read in `--on-cue`; `.iconbtn.is-active`, `.cat-item.is-active` and `.home-tab.is-active` take `--cue-wash` with `--cue` text; native range, checkbox, radio, colour and progress inputs are accent-tinted app-wide. A new control that shows a chosen state uses one of those two forms, never a grey.

The generator clamps lightness; before v0.54.0 the hard ladder emitted `--timescale: #-3-3-3` for High Contrast and Terminal Green, an invalid colour browsers drop.

## Popouts and the home surface

Settings and Studio share one anatomy from `settings.css`: `.set-scrim` holds `.set-pair`, a floating `.set-rail` of `.set-tab` icon rows (the active one accent-filled, a bordered collapse row at the foot) beside a `.set-window` with `.set-head`, a scrolling `.set-body` of `.panel-section` cards and, for Studio, a `.set-foot` status line. Studio pages are `data-view` sections switched by `hidden`; its Stock page (`studio-tools.ts`) searches `/api/stock/search` with kind, query, orientation, size and colour, patches a card grid keyed by item id, and carries the yt-dlp link import. Any surface opens the Studio on a page by dispatching `formcut:studio` on `document` with `{ page }` in `detail`; the media pane's Stock chip does exactly that, and no second stock surface exists since v0.54.1.

The home surface is `.start-overlay`, and `app.css` still declares `place-items: center` on it for the old centred panel; `containers.css` must override both axes (`place-items: stretch`), because overriding only `align-items` leaves `justify-items: center` in force and the whole main column shrinks to its intrinsic width. That was the v0.53.3 homepage defect.

Effect and filter card previews load eagerly at low fetch priority with async decoding. Lazy images inside hidden cards load only when the section is switched to, which shows blank thumbs that fill a moment later.
